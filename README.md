# How Else Could I Say It?

一个关于幽默与日常表达的 Design Research Toolkit（Transformation Design · Culture Probe）。
参与者写下一件日常小事 → 抽幽默技巧卡 → 用新方式重讲 → 打分与反思 → 回看自己的「表达旅程」并提交。

纯静态网站（HTML / CSS / JS），无框架、无外部字体、无 CDN，可直接部署到 GitHub Pages。

## 文件结构

| 想改的内容 | 文件 |
|---|---|
| 颜色（Pastel Meadows 色盘） | `css/theme.css` |
| 12 张绿色技巧卡（含 ? 里的例句）、6 张灰色视角卡（中英文） | `js/cards.js` |
| 界面文字（中英文） | `js/i18n.js` |
| Google 表单、建议轮数、联系方式 | `js/config.js` |
| 游戏流程逻辑 | `js/app.js` |
| 背景漂浮图形 / 彩纸动画 | `js/deco.js` |
| 本地保存、历史记录、复制 | `js/storage.js` |
| 结果卡片图片（反思卡样式） | `js/resultcard.js` |
| 录音的存取（IndexedDB） | `js/audio.js` |
| 样式与动画 | `css/style.css` |
| Google 表单配置助手（研究者用） | `setup.html` |

> 卡牌的 `id` 会写进数据里，开始收集数据后不要再改 `id`（名称、说明、例句可以随便改）。

## 本地预览

```bash
python3 -m http.server 8123
```

在本文件夹里运行，然后打开 http://localhost:8123 。直接双击 `index.html` 也能玩。

## 部署到 GitHub Pages

1. 在 GitHub 新建仓库，把**本文件夹里的内容**放到仓库根目录并推送。
2. 仓库 → Settings → Pages → Source 选 *Deploy from a branch*，Branch 选 `main` / `(root)`。
3. 一两分钟后访问 `https://<你的用户名>.github.io/<仓库名>/`。

## 连接 Google 表单（一键提交）

网站会把答案直接提交到 Google 表单，参与者不用再填一遍。你需要先告诉网站「每道题对应哪个数据」。

**最快的方式：自动建题。** 打开 Google 表单编辑页 → 右上角 ⋮ → **Apps Script**，把 `tools/create-form.gs` 的全部内容粘贴进去，保存后运行 `setupForm`，并授权。它会一次建好所有题目（每道题标题末尾带着数据键名，如 `Participant ID [pid]`），然后在日志里打印出可以直接贴进 `js/config.js` 的 `fields: { … }`。

**手动方式：**

1. 在 Google 表单里为想收集的数据建题，**建议全部用「简答」或「段落」题**（选择题必须和选项文字完全一致，否则会提交失败）。最少只需要 `pid` + `summary_text` + `full_json` 三道题；想在表格里直接分析，再加 `r1_ease` 等分轮字段。
2. 打开部署好的 `…/setup.html`，按页面上的步骤用「获取预填链接」在每道题里填入键名（如 `pid`），把链接粘贴进去，生成配置。
3. 把生成的 `fields: { … }` 替换到 `js/config.js` 里，推送到 GitHub。
4. 表单设置里请确认：**不要求登录、不收集邮箱、不限制每人一次**；网站没有对应数据的题不要设为「必填」。否则后台提交会被 Google 拒绝。
5. 自己完整玩一遍并提交，去表单「回复」页确认数据到了。

`mode: 'direct'` 是后台一键提交；如果遇到问题，改成 `mode: 'prefill'`，提交时会在新标签页打开**已填好的表单**，参与者只需点 Google 的「提交」。

### 如何区分参与者

每次会话自动生成编号，所有导出与提交都带着它：

- `pid`：如 `P261026-1432-K7QX` = 日期 + 时间 + 随机码
- `device_id`：该浏览器的随机编号，同一台设备多次参与可以被关联
- `session_no`：这是该浏览器上的第几次会话
- Google 表单本身也会记录每条回复的提交时间

纯静态网站无法安全地获取 IP 地址（需要服务器或第三方服务），所以没有使用 IP。

### Google 无法访问时（如中国大陆）

提交超时会自动弹出备用方案：**保存结果卡片**（PNG 图片）、**复制文字**、或手动全选文本。可在 `config.js` 的 `researcherContact` 填写你的邮箱 / 微信，参与者会看到并把图片或文字发给你。

## 录音（朗读）

「小事」页和「改写」页都有一个朗读区：可以录音，也可以只勾选「读了，没录音」。

- 录音保存在浏览器的 IndexedDB 里，只留在参与者自己的设备上，刷新不会丢失，可以回放、重录、删除。
- Google 表单收不了音频文件，所以表单里只记录 `story_read_aloud` / `rN_read_aloud`，值为 `recorded (12s)`、`yes` 或 `no`。
- 想收集录音本身：参与者在旅程页点「下载录音」，文件名带着编号（如 `how-else-P261026-1432-K7QX-round1.webm`），和结果卡片一起发给你。Safari 录出来的是 `.m4a`。
- 录音需要麦克风权限和 HTTPS（GitHub Pages 和 localhost 都可以）。不支持或被拒绝时会提示「读出声也可以」。

## 每天一次 · 我的记录

- 设计为每天参与一次。首页会判断：今天的记录可以「继续」；前一天没做完的，首页显示「开始今天的记录」，旧的那次自动存进「我的记录」。
- 一次记录里可以多试几张技巧卡（「换个技巧卡试试」），建议 3 次。
- 「开始新的一次」**不会删除**任何东西，只是把当前这次放进「我的记录」。只有在「我的记录」里点「删除」并确认，才会删掉那一条和它的录音。
- 首页「我的记录」可以按编号查询（输入编号的一部分也行），点开某条可以继续写、重新生成卡片或提交。
- 记录只存在**当时使用的那个浏览器**里（纯静态网站没有服务器，跨设备查询做不到）。关闭浏览器不会清除；但无痕模式、手动清除网站数据、或 Safari 连续 7 天没打开这个网站时，数据可能被清掉。所以结果卡片图片是参与者最稳妥的备份。

## 数据保存

- 每次输入都会自动保存到浏览器 LocalStorage，刷新、关闭页面后可以继续。
- 「保存结果卡片」生成一张 PNG：顶部是原来的故事和编号，下面每一轮一张「表达实验 / 反思卡」（技巧、角度、我的版本、五项评分、反思），最爱的那轮带 ♥。手机上长按图片保存。
- 完整的结构化数据（JSON）仍然会随提交一起进入 Google 表单的 `full_json` 列，参与者不需要管理文件。
- 想开始新一批研究、清空所有人的旧进度：修改 `config.js` 里的 `storageKey`。
